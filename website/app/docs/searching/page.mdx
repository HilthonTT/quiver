# Searching

A search returns the `k` points nearest to a query, closest first. The query is a vector, the id of a point already in the collection, or a sparse vector; [hybrid queries](#hybrid-search) fuse several searches into one ranking. The examples use this collection:

```bash
curl -X POST localhost:6900/collections -H 'content-type: application/json' \
  -d '{"name": "books", "dimension": 3}' > /dev/null
curl -X POST localhost:6900/collections/books/points -H 'content-type: application/json' -d '{
  "points": [
    {"id": "dune",       "vector": [0.9, 0.1, 0.0], "metadata": {"genre": "sci-fi",  "year": 1965}},
    {"id": "foundation", "vector": [0.8, 0.2, 0.1], "metadata": {"genre": "sci-fi",  "year": 1951}},
    {"id": "hobbit",     "vector": [0.1, 0.9, 0.2], "metadata": {"genre": "fantasy", "year": 1937}},
    {"id": "emma",       "vector": [0.0, 0.2, 0.9], "metadata": {"genre": "romance", "year": 1815}}
  ]
}'
```

```json
{"ids":["dune","foundation","hobbit","emma"],"upserted":4}
```

## A search

`POST /collections/{name}/search`:

```bash
curl -X POST localhost:6900/collections/books/search -H 'content-type: application/json' \
  -d '{"vector": [1.0, 0.0, 0.0], "k": 2, "filter": {"genre": "sci-fi"}, "with_vectors": true}'
```

```json
{
  "results": [
    {"distance": 0.006116271018981934, "id": "dune", "metadata": {"genre": "sci-fi", "year": 1965},
     "vector": [0.9938837289810181, 0.11043152958154678, 0.0]},
    {"distance": 0.036913156509399414, "id": "foundation", "metadata": {"genre": "sci-fi", "year": 1951},
     "vector": [0.9630868434906006, 0.24077171087265015, 0.12038585543632507]}
  ]
}
```

| Field | Default | Meaning |
| --- | --- | --- |
| `vector` | | the query; give exactly one of `vector`, `id` and `sparse` |
| `id` | | search with this point's stored vector; the point itself is left out |
| `sparse` | | a [sparse query](#sparse-search), `{"indices": [...], "values": [...]}` |
| `using` | the main vector | the [named vector](#named-vectors) to search; required with `sparse` |
| `k` | 10 | how many results, 1 to 10,000 |
| `filter` | none | a [filter](/docs/filtering/) on metadata |
| `ef` | the collection's `ef_search` | HNSW beam width for this query; ignored by exact indexes |
| `max_distance` | none | drop results farther than this |
| `with_vectors` | `false` | include each result's stored vector |
| `with_metadata` | `true` | include each result's metadata |

Fewer than `k` results come back when fewer points match. Stored vectors are what you get back: with cosine, the normalised ones.

### Recall and `ef`

With an HNSW index the results are approximate. Raise `ef` to trade speed for recall on one query, or set `ef_search` on the collection for all of them; [indexes & metrics](/docs/indexes/) has measured numbers. `ef` is never narrower than `k`.

## Search by id

Give `id` instead of `vector` to find a stored point's neighbours. The point is excluded inside the index, so it does not use up one of the `k`:

```bash
curl -X POST localhost:6900/collections/books/search -H 'content-type: application/json' \
  -d '{"id": "dune", "k": 2, "with_metadata": false}'
```

```json
{"results":[{"distance":0.016214847564697266,"id":"foundation"},{"distance":0.7856534719467163,"id":"hobbit"}]}
```

An id that does not exist answers `404 point_not_found`.

## Recommend

`POST /collections/{name}/recommend` finds points like the `positive` examples and unlike the `negative` ones. The query is the mean of the positives; with negatives, it is pushed away from them: `2 · mean(positive) − mean(negative)`. The examples themselves never appear in the results.

```bash
curl -X POST localhost:6900/collections/books/recommend -H 'content-type: application/json' \
  -d '{"positive": ["hobbit"], "negative": ["dune"], "k": 2}'
```

```json
{"results":[{"distance":0.598021388053894,"id":"emma","metadata":{"genre":"romance","year":1815}},{"distance":1.1261796951293945,"id":"foundation","metadata":{"genre":"sci-fi","year":1951}}]}
```

It takes the same `k`, `filter`, `ef`, `max_distance`, `with_vectors` and `with_metadata` as a search. At least one positive is required, the examples together may number at most 10,000, and every example must exist (`404 point_not_found` names the first missing one).

## Distance thresholds

`max_distance` drops results farther than the threshold. The results are still capped at `k`, and with HNSW the threshold applies to the approximate top `k`: it filters what the search found rather than searching until it runs out of close points.

```bash
curl -X POST localhost:6900/collections/books/search -H 'content-type: application/json' \
  -d '{"vector": [1.0, 0.0, 0.0], "k": 10, "max_distance": 0.1, "with_metadata": false}'
```

```json
{"results":[{"distance":0.006116271018981934,"id":"dune"},{"distance":0.036913156509399414,"id":"foundation"}]}
```

## Named vectors

In a collection with [named vectors](/docs/collections/#named-and-sparse-vectors), `using` picks the one to search; the query must have that vector's dimension. It works for searches by vector and by id (which then use the point's named vector), recommendations and batch searches.

```bash
curl -X POST localhost:6900/collections/papers/search -H 'content-type: application/json' \
  -d '{"vector": [0.5, 0.5], "using": "title", "k": 5}'
```

`with_vectors` returns every vector of each result: `vector`, `vectors` (named) and `sparse_vectors`.

## Sparse search

`sparse` with `using` naming a sparse vector scores points by the dot product of their sparse vector with the query, weighted by IDF if the sparse vector's `modifier` is `idf`. Only points sharing at least one index with the query come back, best first. The search is exact.

```bash
curl -X POST localhost:6900/collections/papers/search -H 'content-type: application/json' \
  -d '{"sparse": {"indices": [17], "values": [1.0]}, "using": "text", "k": 5}'
```

```json
{"results":[{"distance":-0.5,"id":"p1"}]}
```

To keep "lower is closer" everywhere, a sparse hit's `distance` is its **negated score**; `max_distance` applies to it the same way. `filter` works as for dense searches; `ef` has no effect.

## Hybrid search

`POST /collections/{name}/query` runs several searches, typically one dense and one sparse, and fuses their rankings with reciprocal rank fusion: a point at rank `r` (from 1) of a search scores `weight / (k + r)` there, and its scores add up across searches. Rank fusion needs no calibration between distances and keyword scores.

```bash
curl -X POST localhost:6900/collections/papers/query -H 'content-type: application/json' -d '{
  "prefetch": [
    {"vector": [0.1, 0.2, 0.3, 0.4], "limit": 50},
    {"sparse": {"indices": [17, 4], "values": [1.0, 1.0]}, "using": "text", "weight": 2.0}
  ],
  "fusion": {"type": "rrf", "k": 60},
  "k": 10,
  "filter": {"year": {"$gte": 2000}}
}'
```

```json
{"results":[{"id":"p1","score":0.04918033},{"id":"p7","score":0.016129032}]}
```

| Field | Default | Meaning |
| --- | --- | --- |
| `prefetch` | | 1 to 16 searches, each with exactly one of `vector` and `sparse` |
| `prefetch[].using` | the main vector | the named vector to search; required with `sparse` |
| `prefetch[].limit` | `max(k, 50)` | how many of its best hits take part |
| `prefetch[].weight` | 1 | multiplies its contribution; 0 ignores it |
| `prefetch[].ef`, `prefetch[].max_distance` | | as for a search |
| `fusion` | `{"type": "rrf", "k": 60}` | the fusion method and its constant |
| `k` | 10 | how many results |
| `filter` | none | applies to every search |
| `with_vectors`, `with_metadata` | `false`, `true` | as for a search |

Results carry a `score` instead of a `distance`: **higher is better**.

## Quantized vectors on disk

A vector with scalar quantization and `on_disk` keeps its 8-bit codes in memory and the exact vectors [on disk](/docs/storage/#vectors-on-disk). Searches walk the index with the codes, fetching 4 × `k` candidates, then re-rank them by their exact distances from disk. Returned distances and vectors are exact.

[Binary quantization](/docs/indexes/#binary-quantization) always works this way, with the exact vectors on disk or in memory, and fetches 20 × `k` candidates.

## Batch search

`POST /collections/{name}/search/batch` runs up to 256 searches in one request. Each entry takes every search field above, so entries can mix vectors, ids, sparse queries and named vectors. Results come back as one list per search, in order:

```bash
curl -X POST localhost:6900/collections/books/search/batch -H 'content-type: application/json' -d '{
  "searches": [
    {"vector": [0.0, 1.0, 0.0], "k": 1, "with_metadata": false},
    {"id": "emma", "k": 1, "with_metadata": false}
  ]
}'
```

```json
{"results":[[{"distance":0.029505014419555664,"id":"hobbit"}],[{"distance":0.5789401531219482,"id":"hobbit"}]]}
```

If any entry is invalid, the whole batch fails.

## From Python

```python
from quiver import Client

books = Client("http://localhost:6900").collection("books")

print([h.id for h in books.search([1.0, 0.0, 0.0], k=2, filter={"year": {"$lt": 1960}})])
print([h.id for h in books.search_by_id("dune", k=1)])
print([h.id for h in books.recommend(["hobbit"], negative=["dune"], k=1)])
print([h.id for h in books.search([1.0, 0.0, 0.0], k=10, max_distance=0.1, ef=128)])
print([[h.id for h in hits] for hits in books.search_batch([[0, 1, 0], [0, 0, 1]], k=1)])
```

Named, sparse and hybrid searches, on the `papers` collection:

```python
from quiver import Prefetch

papers = Client("http://localhost:6900").collection("papers")
papers.search([0.5, 0.5], k=5, using="title")
papers.search_sparse({17: 1.0}, k=5, using="text")
papers.query(
    [Prefetch(vector=[0.1, 0.2, 0.3, 0.4]), Prefetch(sparse={17: 1.0, 4: 1.0}, using="text", weight=2.0)],
    k=10,
)
```

```text
['foundation', 'hobbit']
['foundation']
['emma']
['dune', 'foundation']
[['hobbit'], ['emma']]
```

`search_batch` sends the same `k`, filter and `ef` with every vector. The [Rust client](/docs/rust-client/) has `SearchRequest::new(vector, k)`, `SearchRequest::by_id(id, k)`, `SearchRequest::sparse(using, vector, k)` and `.using(name)`, and `QueryRequest` for hybrid queries.

## Errors

| Status | Code | When |
| --- | --- | --- |
| 400 | `invalid_argument` | `k` outside 1–10,000, not exactly one of `vector`, `id` and `sparse`, `sparse` without `using`, an unknown or wrong-kind `using`, an invalid sparse vector, more than 256 searches in a batch or 16 prefetches in a query, a negative weight, no positive example |
| 400 | `dimension_mismatch` | the query vector has the wrong length |
| 400 | `invalid_filter` | the filter does not parse |
| 400 | `invalid_body` | malformed JSON or an unknown field |
| 404 | `not_found` | no such collection |
| 404 | `point_not_found` | the `id`, or an example, does not exist |
